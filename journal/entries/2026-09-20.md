## Continued, the Cusdis to Waline correction

While building the site's guest-comments feature, Cusdis was scoped, built, and wired into
all four article templates before it came up that Cusdis had actually been deprecated, its
GitHub repository archived and its hosted backend down since July 2026. This was checked
independently rather than accepted on the report alone, confirmed through the project's own
GitHub notice and several outside sources, before anything was undone.

Waline was chosen in its place, a real, self-hosted comment system rather than a dead one.
Unlike Giscus, Waline genuinely needs a backend, its own server and database, so this was
treated explicitly as a real exception to the site's no-backend rule, not quietly waved
through as compliant with it. Hosting was decided as Vercel serverless plus a free-tier
database, chosen for zero ongoing cost over the more robust paid alternatives, a tradeoff
accepted on purpose rather than defaulted into.

Cusdis was fully removed, its component file and all four template wirings, and Waline was
built and wired in its place, matching Giscus's existing conventions, keyed by the page's
URL, reactions off, theme following the system setting. Before activating it, a first
deployment URL was checked and rejected, it silently redirected through a login page rather
than reaching Waline's server at all. A second URL was verified as a genuine, working
endpoint before being wired in.

Confirmed independently from this side too: the removal was complete, no trace of Cusdis
left in the code, and the Waline component's actual source matches every decision the
documentation claims for it, exactly. The production URL itself couldn't be reached directly
from this side, a container network restriction, not a doubt about the work.
