## Continued, personal site: mobile-first redesign

Asked for the personal site to become mobile-first, naming three real symptoms directly:
code snippets and diagrams pushing outside the mobile view, the header menu doing the same,
and `/projects`' final letter sitting right on the screen edge. Also asked for a layer of
playfulness and interactivity, referencing a Hydra (DuckDB-on-Postgres) developer-brand
writeup, bold color, a mascot, meme-driven microcopy, gamification, plus daisyUI as the
implementation path and a typing-in-progress effect for code blocks.

Confirmed feasibility before writing anything for Claude Code, rather than assuming: cloned
the live site, ran it locally, and measured the actual bugs at a real 375px mobile viewport
instead of reading the CSS and guessing. All three reported symptoms were real. The header
nav overflowed the viewport by about 23px on every page. The code-block and headline
overflow on article pages traced to one exact line: `.article-grid`'s mobile breakpoint used
`grid-template-columns: 1fr` instead of `minmax(0, 1fr)`, removing the containment floor
that let a wide code line stretch the whole grid track past the screen. One root cause
behind what looked like two separate bugs, confirmed by measurement, not assumed.

The Hydra-style ask ran directly against the site's own documented design rule: "not a
bright, saturated, startup-style palette," one functional accent only, no decorative motion
beyond the cursor-blink and hover annotation. That was named directly rather than worked
around quietly. `docs/design.md` was revised with the change dated and reasoned as a
deliberate, bounded loosening, not a silent rewrite of the original decisions, essay body
text keeps its original muted palette, the new boldness is scoped to structural chrome and
interaction only, and parallax/scroll-fades/transitions stay explicitly out.

Declined to copy Hydra's actual duck mascot, since that's their brand asset, not a
reusable pattern, and asked what should carry the personality instead. Chose a combination:
a mark tied to the UMWAYI method's own structure, plus openness to an original character if
one genuinely fit. Then, separately, named a fact that reframed the whole direction: UMWAYI
means shepherd. That connected directly to something already true about the hub, gathering
scattered threads (journal, career prep, settlement engine, routine machine) into one place
and tending them is what a shepherd does, and it's what the hub-and-spoke structure already
does. The personal mark was rebuilt around that meaning specifically: the existing
cursor-blink glyph as the one tending, the six-stage method as what's being gathered, no
literal crook or pastoral imagery, since that would have been a cliché illustration
layered on top of the meaning instead of the meaning read out of the site's own material.

A full `docs/design.md` revision and a scoped Claude Code prompt were produced from this,
both delivered as actual files rather than printed into chat, following the standing rule
added after today's earlier truncation issue.

## Continued, personal site: build completed and independently verified

its own source, to touch only `clip-path`, never removing or reordering real text, so

The six-stage "flock" mark was built as six dots in a converging arc next to the homepage's
